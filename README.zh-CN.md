PS2 游戏《ゲームになったよ！ドクロちゃん ～健康診断大作戦～》（*Game ni Natta yo! Dokuro-chan \~Kenkou Shindan Daisakusen\~*）的非官方 Windows / Linux 移植，根据反编译的代码用 Rust 编写。目标是与原版玩起来完全一致；只修正原版代码中确实存在的错误，所有修正都在下文列出。

整个游戏均已移植：标题画面；樱的房间（主菜单，包括已看过的结局列表、相册、小游戏菜单和挑战模式）；剧情（文字、语音、背景、角色、镜头、淡入淡出、选项、每日地图、小游戏、当日结算、点数分配、结局）和奖励剧本；选项；存档（在游戏菜单中有十二个存档位；在房间中选择“つづきから”读档）；影片（启动时的商标和片头、标题画面的片头、剧情中的过场动画、相册中的影片），由 ps2-video 库（纯 Rust 实现的 MPEG-2 解码器）解码。详细进度见 [docs/moteur.md](docs/moteur.md)（法语）。

> [!IMPORTANT]
> 本仓库及其发布版本**不包含任何受版权保护的文件**：既没有游戏素材，也没有原版代码。你需要自备原版游戏：游戏显示和播放的一切内容都从中读取。

移植版会读取你放在其可执行文件旁边的光盘镜像，并在启动前校验其 CRC32。镜像也可以放在别处：在存档文件的 `"assets"` → `"path"` 中填写它的路径（或其所在文件夹）；相对路径以可执行文件所在位置为起点。CRC32 只在首次启动时校验（需要几秒钟），之后会根据镜像的大小和日期识别它（`"assets"` → `"checked"`）。

存档文件在 Windows 上保存到 `Documents\My Games`（即 Windows 所认定的“文档”文件夹，移动过或同步的也可以），在 Linux 上保存到 `~/.local/share`。如果在可执行文件旁边放一个 `portable.txt` 文件，存档会改为保存到可执行文件旁边的 `saves` 文件夹中。

## 小游戏

以下是从游戏内菜单启动时的小游戏：

- **ドクロちゃん捕縛アミ**（*捕捉朵库萝的网*）：朵库萝从九个草丛中探出头来；用网捉到她会减少她的槽，挥空则会让槽回升。在 40 秒内把槽清空即获胜。
- **アドバンスド徒競走**（*进阶赛跑*）：与朵库萝赛跑。连按 ○ 奔跑，↑ 跳过栏架，↓ 滑铲；撞到障碍物樱会晕倒，撞到栏架则会停下。先到达终点即获胜。
- **水着で神経衰弱**（*泳装翻牌配对*）：与会记住看过的牌的朵库萝进行翻牌配对。一对牌得 2 分并可再翻一次；鬼牌得 1 分，并会让所有牌短暂翻开。先得 8 分即获胜。
- **桜くん私物キャッチ**（*接住樱的私人物品*）：朵库萝把樱的私人物品从窗户扔出去。物品落地或接到炸弹都会失去三颗心中的一颗。坚持 50 秒即获胜。
- **バッティングエスカリボルグ**（*击球 Escalibolg*）：朵库萝用她的球棒击打樱，需要依次停下三个槽（力量、时机、角度）。在三次尝试内打出 600 m 以上即获胜。

小游戏在剧情中游玩，在剧情中玩过之后，也可以从樱的房间的小游戏菜单中游玩。该菜单还提供挑战模式（连续进行五个难度更高的小游戏，每个都会以骷髅标记计分，达到 100 分即通关）、选择为樱加油的角色，以及教程。看过一个结局后会开放挑战菜单；通关挑战后会在那里开放奖励剧本“12歳の世界！”，其结局会回到房间。

## 游玩

- 所需文件：日版光盘（SLPM-66186，CRC32 `B9F5F0C5`）的光盘镜像（ISO），文件名任意，只要以 `.iso` 结尾即可。
- 将其放在 `dokuro_chan_ps2.exe`（Linux 上为 `dokuro_chan_ps2`）旁边，然后运行该程序。
- 与 PS2 一样用手柄游玩：A 为 ○，B 为 ×，X 为 □，Y 为 △，LB 和 RB 为 L1 和 R1，扳机键为 L2 和 R2，十字键或左摇杆；Start + Select 退出。在剧情中，△ 开始或停止快进，START 开启自动模式，R1 在跳过已读（既読）和全部跳过（強制）之间切换，×、□ 或 L1 会停止它们；对应的标志显示在右上角。镜头晃动时，手柄会像 DualShock 2 一样震动：大马达对应低频马达，小马达对应高频马达（在 Linux 上，手柄的 `/dev/input/event*` 设备必须可写）。
- 键盘：Enter 或 Z 为 ○，Backspace 或 X 为 ×，Escape 为 ×（在剧情中为 □，即菜单），C 为 □，V 为 △，Q、W、A、S 为 L1、R1、L2、R2（在剧情中 A 为自动模式），方向键。赛跑时，空格跳跃，Ctrl 滑铲；其他时候空格为 START。
- 剧情中的操作与 PC 上的视觉小说相同：左键单击、Enter 或滚轮向下翻到下一页；右键（×）隐藏窗口；滚轮向上（L1）打开历史记录，在其中用滚轮滚动（△ 让剧情回到所选页面，□ 打开菜单）；Escape 打开菜单（与原版一样，在选项和地图中也可以）；按住 Ctrl 时持续快进；A 切换自动模式。
- 播放影片时：与原版一样，START（空格）可停止播放；Escape 和单击也可以。前半秒内不响应。
- 鼠标在所有地方遵循同一规则：将鼠标移到菜单项、选项答案、设置值、记忆卡文件、相册缩略图、标签或页面、点数分配格、地图地点或为樱加油的角色头像上，光标就会移到那里；单击它即为 ○，单击旁边则不会有任何反应。在游戏等待任意按键的地方，单击任何位置都可以：在标题画面上相当于 START；在剧情中会推进文字。右键为 ×。单击设置中的槽（音量、不透明度、速度）可以直接设定数值。在小游戏中，网会瞄准鼠标所在的草丛，翻牌游戏会选中鼠标所在的牌，接物品游戏中樱会跟随鼠标。鼠标指针是朵库萝的 Escalibolg（游戏中未使用的图像）；一旦使用键盘或手柄，或鼠标 3 秒未动，它就会隐藏。
- PS2 画面（640 × 448）以 4:3、每秒 60 帧显示。
- Alt+Enter 或 F11：无边框全屏。
- 存档文件（显示模式；游戏在多周目之间保留的内容——已看过的结局、挑战通关、玩过的小游戏、已读页面、选项设置、相册中看过的图像——；十二个存档；以及光盘镜像的路径和校验信息）：Windows 上为 `Documents\My Games\Game ni Natta yo! Dokuro-chan Kenkou Shindan Daisakusen\save.json`，Linux 上为 `~/.local/share/Game ni Natta yo! Dokuro-chan Kenkou Shindan Daisakusen/save.json`。

### 已修正的游戏 bug

本移植只修正游戏代码能证明是错误的地方（凡是可能出于有意设计的都不修改）。每一条都说明：游戏的行为、为何是错误、移植版的做法。

- 挑战失败时画面不变暗：成功时，游戏用 `AD_BlackOutStart(10, 5, 0, 0x50)`（图层 0，不透明度 0x50）让平面 5 变暗；失败时，它调用 `AD_BlackOutStart(10, 5, 0x50, 0x7f)`，即图层 0x50，而一个平面只有两个图层。没有任何可见的东西变暗（游戏写到了它的淡入淡出表之外），而关闭消息时会清除图层 0，画面便一下子变暗，然后再变亮。移植版像成功时一样让画面变暗（10 帧内到 0x50）。
- 提示消息关闭时不会缩小：`AD_InformationWinDel` 连续执行两个阶段（10 帧，然后缩小到 0 × 0），但窗口引擎（`AD_WindowProc`）在阶段之间不会重置帧计数。于是第二阶段一开始就已经结束，消息瞬间消失；同样的疏忽也会让交给仍在打开中的窗口的阶段瞬间结束。移植版在每个阶段重置计数：消息（无论来自挑战还是剧情）都会缩小着关闭。
- 赛跑：两名跑者共用的 `MiniRunHitDown` 把她们的高度与 294（樱那条跑道的地面）比较。站在自己地面上的朵库萝被当作在空中，在与栏架平齐时会短暂回到跳跃姿势。移植版把每名跑者与她自己的地面比较。
- 选项：离开“スキップ・オートプレイ設定”窗口时，游戏把光标放在游戏设置窗口的第 4 项上，然后在同一帧中又用所离开窗口的四个项目数让光标回绕：光标回到顶部的“スキップモード”，返回音之后还会响起移动音。同样的判断也会在打开某个快进模式的详情时，在确认音之后加上这个音。移植版让光标留在第 4 项，只播放返回音（或确认音）。
- 镜头晃动：切换到类型 0x1b（三个轴，8 帧）时，游戏忘了对缩放应用过渡系数，缩放因此会一下子跳到新的晃动，而不像其他类型那样平滑过渡。移植版会应用该系数。
- 窗口：当一个动作在动画进行到一半时被另一个动作取代（例如窗口在打开过程中被关闭），`AD_WinActSet` 用 `(float)(count / duration)` 计算该阶段的进度，这是在类型转换之前进行的整数除法：在阶段结束之前结果一直为 0，而后续的计算（起点 + 进度 × (目标 − 起点)）需要的是小数。窗口因此会一下子跳回该阶段的起点。移植版用小数相除：窗口从它当时的位置继续。
- 相册的奖励图像：在集齐相册获得的奖励图像之后，游戏本应等待 0x14 帧让黑幕落下再显示相册，但它的判断条件写反了（只有当计数已经小于 1 时才递减，否则直接继续）：相册立刻出现，黑幕来不及落下。移植版会等待这 0x14 帧。
- 自动模式右上角的标志：“オート”“強制スキップ”“既読スキップ”这几个标签是 `win2` 图像中 119 × 21 像素的图，位于第 2、26、50 行。游戏正确地裁出了后两个，但“オート”是从第 0 行开始裁的：顶部多了两行空白，底边的两行缺失，标签看起来被切掉了。移植版从第 2 行开始裁。
- 循环音效：游戏在两个槽位中各自记录循环音效的编号，只在启动时（`AD_SoundInit`）重置。在循环音效播放的场景中回到房间，声音会停止，但编号仍被保留；在下一局游戏中，从游戏菜单打开选项或记忆卡，返回时就会重新播放它（`AD_LoopSERePlay`），直到某个脚本停止该槽位为止。移植版在离开剧情时清除这些循环。

### 游戏中存在但从未使用的内容

研究可执行文件和光盘上的 35 个脚本（`Tools/coverage.py` 的报告）可以发现一些存在但无法到达的代码，大概是在开发过程中被放弃的。由于游戏本身无法到达它们，移植版没有将其恢复。

- 一个对战模式（`AD_Dcb*` 函数，约 40 KB 代码）。玩家选择一名角色，然后在正确的时机按键：一个标记绕着放有目标的圆圈转动，每击中一个目标就得分。此外还有体力、槽、全屏特写、援护、回合、背景中的枪（`dcbgun`）以及胜利和失败画面（`dcb_win`、`dcb_lose`）。它会在剧情的背景上、用剧情的角色进行。剧情本应通过类型 6 的批次启动它，但没有任何脚本指令会产生这一类型；它的十五张图像和角色表也都不在光盘上。
- 一个数字键盘（`AD_TenKey*` 函数，批次类型 5），按电话键盘排列（1 到 9、*、0、#），用来让玩家拨一个号码，并带有答对和答错的文字：它的指令（`tenkey_mode`、`tenkey_ok_text_set`、`tenkey_ng_text_set`）没有出现在任何脚本中，它的两张图像（`tenkey`、`tenkeybg`）也不在光盘上。
- 一个精灵与 3D 模型引擎（`SP_SYSTEM`、`MGP2`、粒子、变形），每一帧都在运行但始终是空的：没有脚本使用它的指令。
- 相册的奖励图像，根据某个标志或在相册集齐时于游戏最后显示（`AD_CgBonusGetJudg`）：没有脚本登记任何此类图像（`bonus_cg_flag_entry`、`bonus_cg_spflag_entry`、`bonus_cg_comp_entry`）。实际只使用了小游戏的奖励图像。移植版保留了这一机制，它与原版一样不会被使用。
- 标题画面上一个没有任何地方会打开的“是 / 否”问题。
- 房间中一个本应开始另一段序章的项目（`AD_AdvPartStartProc(0)`）：没有脚本登记它（`prologue_stcm`），菜单中也没有它的图像；光标会跳过它。
- 在脚本 3 中，所有影片又以开发用路径（`host0:pss/…`，从开发电脑读取的文件）重新登记了一次，位于游戏从不执行的部分。

### 与 PS2 版的差异

- 没有读盘等待：在游戏等待数据载入（`AD_DataReadStateGet`）或音乐停止的地方，移植版会直接继续。因此影片会在前一页之后更快开始，剧情也会在影片之后更快恢复。
- 剧情影片之后，重新开始的音乐要过四分之一秒才会听到。游戏会重新播放音乐，而当下一个场景是静音时又会立刻停止它：在 PS2 上，读盘时间使它听不到，而读取瞬间完成的移植版则会让它短暂响起。其他所有音乐都会立即开始。
- 影片解码完全准确，但以一半分辨率存储的色彩是在采样点之间插值的，而不是像主机的 IPU 那样以 2 × 2 的块重复：色彩边缘更清晰，画面本身没有添加任何东西。影片的声音与 PS2 一样以最大音量播放。
- 在游戏把系统数据写入记忆卡的地方（离开已修改的选项时），移植版会写入它的存档文件，而不显示记忆卡画面。保留的标志在发生变化时立即写入；已读页面在每次等待时写入（翻页、选项、地图），也就是游戏把它们与系统数据一起复制的时候；用 R1 选择的快进模式在存档时写入。
- 游戏存档会通过游戏自己的记忆卡画面、消息和问题保存到移植版的存档文件中（第一次时，会像在新的记忆卡上一样提示创建游戏数据）。不会出现记忆卡缺失、已满或损坏的错误。操作是瞬间完成的：其消息会显示半秒。

## 校验文件

CRC32 可以判断光盘镜像是否为正确的版本。可以用 7-Zip（右键 > CRC SHA > CRC-32）或 Python 校验：

```
python Tools/crc32.py <文件>
```

## 构建

需要：[Rust](https://rustup.rs)（stable）。

### Windows

```
build.bat
```

以 release 模式构建移植版，并生成可直接分发的压缩包（仅含可执行文件，不含游戏文件）：`target\Dokuro-chan.PS2.Windows.zip`。

### Linux

还需要 `pkg-config` 和 ALSA 头文件（Ubuntu 上：`sudo apt install pkg-config libasound2-dev`）。在 Linux 上：

```
./build.sh
```

在 Windows 上，`build_linux.bat` 会在 WSL（Ubuntu）中完成同样的工作。压缩包生成在 `target/Dokuro-chan.PS2.Linux.tar.gz`。

### 重新进行研究

一切都可以从放在仓库根目录的 ISO 重新做起（详见 `Tools/README.md`，法语）：

1. `Tools\decompile.bat <Ghidra 文件夹>`：从 ISO 中取出的可执行文件、其函数名，以及整个游戏在 `decompiled/` 中的伪 C 代码。
2. `python -I Tools/uni_extract.py <iso> UNION/SCRIPT.UNI Tools/work/script`：剧情脚本。
3. `python -I Tools/stcm2_table.py Tools/work/SLPM_661.86 Tools/work/symbols.txt > Tools/work/stcm2_opcodes.txt`，然后 `python -I Tools/stcm2_dump.py <脚本>.bin Tools/work/stcm2_opcodes.txt`：可读文本形式的脚本。
4. `python -I Tools/uni_png.py <iso> <扇区> <文件夹>`：一个资源包中的图像（扇区由 `Tools/iso_list.py` 给出）；`python -I Tools/sprites_png.py <iso> <文件夹>` 可一次导出游戏的全部图像。

### 测试

`cargo test`：运行测试（读取真实脚本的测试只在仓库根目录有 ISO 时运行）。在 debug 构建中，可以用环境变量驱动游戏而无需盯着窗口：`DOKURO_SNAPSHOT=<帧>:<文件.png>`（截取一张图后退出游戏）、`DOKURO_EVERY=<n>[@<帧>]`（从该帧起每 n 帧截一张图）、`DOKURO_INPUT=<帧>[-<帧>]:<按键>;…`（按下按键，或从一帧按住到另一帧）、`DOKURO_STORY=<脚本>[:<入口点>]`（从该处开始剧情，例如 `102:sure2`）、`DOKURO_TRACE=1`（把执行过的每个入口点写到标准错误输出：足以让剧情从要测试的地方之前重新开始）、`DOKURO_BOOT=1`（启动影片，否则测试会跳过它们，直接从标题画面开始）以及 `DOKURO_ZONES=1`（用红框标出画面上的鼠标区域）。`cargo test audit -- --ignored --nocapture` 会在没有窗口的情况下用真实脚本走一遍剧情（每个选项选第一个答案，地图选第一个地点），列出缩放、镜头偏移、晃动、淡入淡出平面或画面外角色持续十页以上的场景，以及它开始的入口点和批次，还有途中遇到的影片；`DOKURO_AUDIT=<脚本>:<入口点>` 可以从别处开始（例如某个结局：`121:sure1`）。

在 Windows 上，`Tools\Tester.bat` 通过菜单设置这些变量，然后启动游戏、剧情检查（audit）或测试。

在 debug 构建中，移植版也会在本仓库的根目录寻找光盘镜像（`*.iso` 不纳入 git）。
