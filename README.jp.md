PS2 用ソフト『ゲームになったよ！ドクロちゃん ～健康診断大作戦～』の、非公式の Windows / Linux 移植です。逆コンパイルしたコードをもとに Rust で書かれています。オリジナルとまったく同じ遊び心地を目指しており、修正しているのはコード上の明らかな誤りだけです。修正点はすべて下に記載しています。

ゲーム全体が移植済みです：タイトル画面、桜くんの部屋（メインメニュー。見たエンディングの一覧、アルバム、ミニゲームメニュー、チャレンジモード）、本編（テキスト、ボイス、背景、キャラクター、カメラ、フェード、選択肢、マップ、ミニゲーム、一日の結果、ポイントの振り分け、エンディング）とボーナスシナリオ、オプション、セーブ（ゲームメニューから 12 ファイル。部屋の「つづきから」）、ムービー（起動時のロゴとオープニング、タイトル画面のオープニング、本編のムービー、アルバムのムービー）。ムービーは ps2-video ライブラリ（純粋な Rust による MPEG-2 デコーダ）でデコードしています。詳しい状況は [docs/moteur.md](docs/moteur.md)（フランス語）にあります。

このリポジトリには**著作権のあるファイルは一切含まれていません**：ゲームの素材も、オリジナルのコードもありません。移植版は、実行ファイルの隣に置かれたディスクイメージを読み込み、起動前に CRC32 で確認します。イメージは別の場所に置くこともできます：セーブファイルの `"assets"` → `"path"` にそのパス（またはそれを含むフォルダ）を指定してください。相対パスは実行ファイルの場所が基準です。CRC32 の確認は初回起動時のみ（数秒）で、その後はサイズと日付でイメージを判別します（`"assets"` → `"checked"`）。

セーブファイルは、Windows では `Documents\My Games`（Windows が認識しているドキュメントフォルダ。移動や同期をしていても可）、Linux では `~/.local/share` に保存されます。実行ファイルの隣に `portable.txt` を置くと、代わりに実行ファイルの隣の `saves` フォルダに保存されます。

## ミニゲーム

ゲーム内のメニューから始めた場合のミニゲーム：

- **ドクロちゃん捕縛アミ**：ドクロちゃんが九つの茂みから顔を出します。アミで捕まえるとゲージが減り、空振りすると増えます。40 秒以内にゲージを空にすれば勝ち。
- **アドバンスド徒競走**：ドクロちゃんとの徒競走。○ の連打で走り、↑ でハードルを跳び、↓ でスライディング。障害物に当たると桜くんは気絶し、ハードルに当たると止まります。先にゴールすれば勝ち。
- **水着で神経衰弱**：見たカードを覚えているドクロちゃんとの神経衰弱。ペアは 2 点でもう一度引けます。ジョーカーは 1 点で、すべてのカードが一瞬見えます。8 点で勝ち。
- **桜くん私物キャッチ**：ドクロちゃんが桜くんの私物を窓から投げます。物が地面に落ちるか、爆弾を取ると、三つのハートが一つ減ります。50 秒耐えれば勝ち。
- **バッティングエスカリボルグ**：ドクロちゃんがバットで桜くんを打ちます。三つのゲージ（パワー、タイミング、角度）を止めて飛ばします。三回の挑戦で 600 m を超えれば勝ち。

ミニゲームは本編の中で遊び、本編で一度遊ぶと桜くんの部屋のミニゲームメニューからも遊べるようになります。このメニューには、チャレンジモード（五つのゲームを続けて、難しくなった状態で遊び、それぞれドクロマークで点数が入ります。100 点でクリア）、応援するキャラクターの選択、チュートリアルもあります。チャレンジのメニューはエンディングを一度見ると開き、チャレンジをクリアするとそこでボーナスシナリオ「12歳の世界！」が開きます。ボーナスシナリオの最後は部屋に戻ります。

## 遊び方

- 必要なファイル：日本版ディスク（SLPM-66186、CRC32 `B9F5F0C5`）のディスクイメージ（ISO）。名前は `.iso` で終わっていれば何でもかまいません。
- `dokuro_chan_ps2.exe`（Linux では `dokuro_chan_ps2`）の隣に置いて、実行ファイルを起動してください。
- PS2 と同じようにゲームパッドで遊べます：A が ○、B が ×、X が □、Y が △、LB と RB が L1 と R1、トリガーが L2 と R2、十字キーまたは左スティック。Start + Select で終了します。本編では、△ でスキップの開始・停止、START でオートモード、R1 で既読スキップと強制スキップの切り替え、×・□・L1 でそれらを止めます。右上にその表示が出ます。カメラが揺れると DualShock 2 と同じようにゲームパッドが振動します：大きいモーターは低周波モーター、小さいモーターは高周波モーターで再現します（Linux では、ゲームパッドの `/dev/input/event*` デバイスに書き込めるようにしておく必要があります）。
- キーボード：Enter または Z が ○、Backspace または X が ×、Escape が ×（本編では □、つまりメニュー）、C が □、V が △、Q・W・A・S が L1・R1・L2・R2（本編では A がオートモード）、矢印キー。徒競走ではスペースでジャンプ、Ctrl でスライディング。それ以外ではスペースが START です。
- 本編は PC のノベルゲームと同じ操作です：左クリック、Enter、ホイール下で次のページ。右クリック（×）でウィンドウを隠します。ホイール上（L1）で履歴を開き、履歴の中はホイールでスクロールします（△ で選んだページまで本編を戻し、□ でメニューを開きます）。Escape でメニューを開きます（ゲームと同じく、選択肢やマップの最中も可）。Ctrl を押している間はスキップ、A でオートモードの切り替え。
- ムービー中：ゲームと同じく START（スペース）で止まります。Escape とクリックでも止まります。最初の 0.5 秒は受け付けません。
- マウスはどこでも同じ規則です：メニュー項目、選択肢の答え、オプションの値、メモリーカードのファイル、アルバムのサムネイル・タブ・シート、ポイント振り分けのマス、マップの場所、応援するキャラクターの肖像にマウスを乗せるとカーソルがそこへ移り、クリックすると ○ になります。何もない場所をクリックしても何も起きません。ゲームが何かのキー入力を待っている場面では、どこをクリックしてもかまいません：タイトル画面では START、本編ではテキストが進みます。右ボタンは × です。オプションのゲージ（音量、不透明度、速度）はクリックした位置に直接設定されます。ミニゲームでは、アミはマウスを乗せた茂みを狙い、神経衰弱はマウスを乗せたカードを選び、私物キャッチでは桜くんがマウスについていきます。ポインターはドクロちゃんのエスカリボルグ（ゲーム内で使われていなかった画像）です。キーボードやゲームパッドを使うとすぐに、またはマウスを 3 秒触らないと消えます。
- PS2 の画面（640 × 448）を 4:3、60 フレーム毎秒で表示します。
- Alt+Enter または F11：ボーダーレスのフルスクリーン。
- セーブファイル（表示モード、ゲームが周回をまたいで保持するもの —— 見たエンディング、チャレンジのクリア、遊んだミニゲーム、既読ページ、オプションの設定、アルバムで見た画像 ——、12 個のセーブデータ、ディスクイメージのパスと確認情報）：Windows では `Documents\My Games\Game ni Natta yo! Dokuro-chan Kenkou Shindan Daisakusen\save.json`、Linux では `~/.local/share/Game ni Natta yo! Dokuro-chan Kenkou Shindan Daisakusen/save.json`。

### 修正したゲームのバグ

この移植では、ゲームのコードから誤りだと証明できるものだけを修正しています（意図した動作の可能性があるものは修正しません）。それぞれについて、ゲームの動作、それが誤りである理由、移植版の動作を記します。

- チャレンジ失敗時に画面が暗くならない：成功時、ゲームは `AD_BlackOutStart(10, 5, 0, 0x50)`（レイヤー 0、不透明度 0x50）でプレーン 5 を暗くします。失敗時は `AD_BlackOutStart(10, 5, 0x50, 0x7f)` を呼び、レイヤー 0x50 を指定しますが、プレーンにはレイヤーが二つしかありません。目に見えるものは何も暗くならず（ゲームはフェードの表の外に書き込みます）、メッセージを閉じるとレイヤー 0 が消去されるため、画面が一瞬で暗くなってから明るくなります。移植版では成功時と同じように画面を暗くします（10 フレームで 0x50）。
- お知らせメッセージが閉じるときに縮まない：`AD_InformationWinDel` は二つの段階（10 フレーム、次に 0 × 0 までの縮小）を続けますが、ウィンドウ処理（`AD_WindowProc`）は段階ごとにフレーム数をリセットしません。そのため二段階目は最初から終わった状態で始まり、メッセージは一瞬で消えます。同じ見落としにより、開いている途中のウィンドウに与えた段階も一瞬で終わります。移植版では段階ごとにフレーム数をリセットするので、メッセージ（チャレンジのものも本編のものも）は縮みながら閉じます。
- 徒競走：二人の走者に共通の `MiniRunHitDown` は、走者の高さを桜くんのレーンの地面である 294 と比べます。自分の地面にいるドクロちゃんは空中にいるとみなされ、ハードルの位置で一瞬ジャンプのポーズに戻ります。移植版ではそれぞれの走者を自分の地面と比べます。
- オプション：「スキップ・オートプレイ設定」のウィンドウを出るとき、ゲームはカーソルをゲーム設定ウィンドウの項目 4 に置き、同じフレームの中で、出てきたウィンドウの四つの項目数でカーソルを折り返します。カーソルは先頭の「スキップモード」に戻り、戻る音のあとに移動音が鳴ります。同じ判定により、スキップモードの詳細を開くときも決定音のあとにその音が加わります。移植版ではカーソルを項目 4 に残し、戻る音（または決定音）だけを鳴らします。
- カメラの揺れ：種類 0x1b（三つの軸すべて、8 フレーム）に切り替えるとき、ゲームはズームに切り替えの係数をかけ忘れるため、ズームは他の種類のように新しい揺れへなめらかに移らず、一瞬で切り替わります。移植版では係数をかけます。
- ウィンドウ：動きの途中で別の動きに置き換えられるとき（たとえば開いている途中のウィンドウが閉じるとき）、`AD_WinActSet` は段階の進み具合を `(float)(count / duration)` で計算します。変換の前に整数の割り算をしているため、段階が終わるまで値は 0 になります。一方、続く計算（開始値 + 進み具合 × (目標値 − 開始値)）は小数を前提としています。そのためウィンドウは一瞬で段階の最初に戻ります。移植版では小数で割り算をするので、ウィンドウはその位置から続きます。
- アルバムのボーナス画像：アルバムを完成させて手に入るボーナス画像のあと、ゲームは黒が下りるまで 0x14 フレーム待ってからアルバムを表示するはずですが、判定が逆になっています（カウントがすでに 1 未満のときだけ減らし、それ以外はすぐ次へ進みます）。そのためアルバムは黒が下りる前にすぐ表示されます。移植版では 0x14 フレーム待ちます。
- オートモード、右上の表示：「オート」「強制スキップ」「既読スキップ」の表示は `win2` 画像の中にある 119 × 21 ピクセルの絵で、行 2、26、50 にあります。ゲームは後ろの二つを正しく切り出しますが、「オート」は行 0 から切り出しています。上に空の行が二つ入り、下の縁の二行が欠けるため、表示が切れて見えます。移植版では行 2 から切り出します。
- ループする効果音：ゲームは二つのスロットそれぞれにループの番号を保持し、起動時（`AD_SoundInit`）にしかリセットしません。ループが鳴っている場面で部屋に戻ると、音は止まりますが番号は残ります。次のゲームで、ゲームメニューからオプションやメモリーカードを開くと、戻ったときにその音が再開し（`AD_LoopSERePlay`）、スクリプトがそのスロットを止めるまで鳴り続けます。移植版では本編を出るときにループの番号を消去します。

### ゲームに含まれているが使われていないもの

実行ファイルとディスクの 35 個のスクリプトを調べると（`Tools/coverage.py` の集計）、存在はするものの到達できないコードが見つかります。おそらく開発途中で放棄されたものです。ゲーム自体が到達できないため、移植版では復活させていません。

- バトルモード（`AD_Dcb*` 関数、約 40 KB のコード）。キャラクターを選び、タイミングよくボタンを押します：ターゲットが置かれた円の上をマーカーが回り、ターゲットに当てるごとに点数が入ります。そのほかに、体力、ゲージ、全画面のカットイン、援護、ターン、背景の銃（`dcbgun`）、勝利と敗北の画面（`dcb_win`、`dcb_lose`）があります。本編の背景とキャラクターで遊ぶ作りです。本編からは種類 6 のバッチで始まるはずですが、その種類を作るスクリプト命令はありません。また、15 枚の画像もキャラクターの表もディスクにはありません。
- 電話のキーパッドのような配置（1 ～ 9、*、0、#）のテンキー（`AD_TenKey*` 関数、バッチの種類 5）。プレイヤーに番号を入力させるためのもので、正解と不正解のテキストもあります。その命令（`tenkey_mode`、`tenkey_ok_text_set`、`tenkey_ng_text_set`）はどのスクリプトにも出てこず、二枚の画像（`tenkey`、`tenkeybg`）もディスクにありません。
- スプライトと 3D モデルのエンジン（`SP_SYSTEM`、`MGP2`、パーティクル、モーフィング）。毎フレーム動いていますが中身は空です：その命令を使うスクリプトはありません。
- アルバムのボーナス画像。フラグに応じて、またはアルバムが完成したときにゲームの最後に表示されるもの（`AD_CgBonusGetJudg`）ですが、登録するスクリプトはありません（`bonus_cg_flag_entry`、`bonus_cg_spflag_entry`、`bonus_cg_comp_entry`）。使われているのはミニゲームのボーナス画像だけです。移植版はこの仕組みを残していますが、ゲームと同じく使われません。
- タイトル画面の、何からも開かれない「はい / いいえ」の質問。
- 部屋の中の、別のプロローグを始めるはずの項目（`AD_AdvPartStartProc(0)`）。登録するスクリプトはなく（`prologue_stcm`）、メニューにもその画像がありません。カーソルはこの項目を飛ばします。
- スクリプト 3 の中で、すべてのムービーが開発用のパス（`host0:pss/…`、開発用 PC から読み込むファイル）でもう一度登録されている部分。ゲームはこの部分を実行しません。

### PS2 版との違い

- ディスクの読み込み待ちはありません：ゲームがデータの読み込み（`AD_DataReadStateGet`）や音楽が止まるのを待つ場面でも、移植版はすぐに先へ進みます。そのため、ムービーはその前のページのあと早めに始まり、本編もムービーのあと早めに再開します。
- 本編のムービーのあと、再開した音楽は 0.25 秒たってから聞こえます。ゲームは音楽を再開し、次の場面が無音ならすぐに止めます：PS2 ではディスクの読み込み時間のおかげで聞こえませんでしたが、読み込みが一瞬で終わる移植版では一瞬だけ音楽が戻っていました。それ以外の音楽はすぐに始まります。
- ムービーは正確にデコードしていますが、半分の解像度で記録された色は、本体の IPU のように 2 × 2 のブロックで繰り返さず、サンプルの間を補間しています：色の境目がよりくっきりし、映像に何かを加えることはありません。音声は PS2 と同じく最大音量で再生します。
- ゲームがメモリーカードにシステムデータを書き込む場面（変更したオプションを閉じたとき）では、移植版はメモリーカード画面なしでセーブファイルに書き込みます。保持されるフラグは変わった時点で、既読ページはゲームがシステムデータと一緒にコピーする各待ち（ページ、選択肢、マップ）で、R1 で選んだスキップモードはゲームをセーブしたときに書き込みます。
- セーブデータは、ゲーム自身のメモリーカード画面、メッセージ、質問を通して、移植版のセーブファイルに保存されます（初回は、新しいメモリーカードと同じようにゲームデータの作成を勧めます）。メモリーカードがない、空きがない、壊れているといったエラーは起こりません。処理は一瞬で終わり、そのメッセージは 0.5 秒表示されます。

## ファイルの確認

CRC32 でディスクイメージが正しい版かどうかがわかります。7-Zip（右クリック > CRC SHA > CRC-32）または Python で確認できます：

```
python Tools/crc32.py <ファイル>
```

## ビルド

必要なもの：[Rust](https://rustup.rs)（stable）。

### Windows

```
build.bat
```

移植版をリリースビルドし、配布用のアーカイブ（実行ファイルのみ、ゲームのファイルは含みません）を作ります：`target\Dokuro-chan.PS2.Windows.zip`。

### Linux

`pkg-config` と ALSA のヘッダーも必要です（Ubuntu では `sudo apt install pkg-config libasound2-dev`）。Linux で：

```
./build.sh
```

Windows からは、`build_linux.bat` が WSL（Ubuntu）で同じことを行います。アーカイブは `target/Dokuro-chan.PS2.Linux.tar.gz` に作られます。

### 調査のやり直し

すべて、リポジトリの直下に置いた ISO からやり直せます（詳しくは `Tools/README.md`、フランス語）：

1. `Tools\decompile.bat <Ghidra のフォルダ>`：ISO から取り出した実行ファイル、関数名、`decompiled/` にゲーム全体の疑似 C。
2. `python -I Tools/uni_extract.py <iso> UNION/SCRIPT.UNI Tools/work/script`：本編のスクリプト。
3. `python -I Tools/stcm2_table.py Tools/work/SLPM_661.86 Tools/work/symbols.txt > Tools/work/stcm2_opcodes.txt`、次に `python -I Tools/stcm2_dump.py <スクリプト>.bin Tools/work/stcm2_opcodes.txt`：読めるテキストにしたスクリプト。
4. `python -I Tools/uni_png.py <iso> <セクター> <フォルダ>`：パッケージの画像（セクターは `Tools/iso_list.py` で調べます）。ゲームのすべての画像は `python -I Tools/sprites_png.py <iso> <フォルダ>` で一度に書き出せます。

### テスト

`cargo test`：テスト（本物のスクリプトを読むテストは、リポジトリの直下に ISO があるときだけ実行されます）。デバッグビルドでは、環境変数でウィンドウを見ずにゲームを操作できます：`DOKURO_SNAPSHOT=<フレーム>:<ファイル.png>`（画面を一枚保存して終了）、`DOKURO_EVERY=<n>[@<フレーム>]`（そのフレームから n フレームごとに保存）、`DOKURO_INPUT=<フレーム>[-<フレーム>]:<ボタン>;…`（ボタンを押す、またはあるフレームから別のフレームまで押し続ける）、`DOKURO_STORY=<スクリプト>[:<エントリーポイント>]`（その場所から本編を始める。例：`102:sure2`）、`DOKURO_TRACE=1`（実行したエントリーポイントを標準エラー出力に書く。テストしたい場面の直前から本編を始め直すのに使えます）、`DOKURO_BOOT=1`（起動時のムービー。指定しないとテストはタイトル画面から始まります）、`DOKURO_ZONES=1`（画面のマウス判定の範囲を赤い枠で表示）。`cargo test audit -- --ignored --nocapture` は、本物のスクリプトでウィンドウなしに本編をたどり（各選択肢の最初の答え、マップの最初の場所）、ズーム、カメラのずれ、揺れ、フェードのプレーン、画面外のキャラクターが 10 ページ以上続く場面を、始まるエントリーポイントとバッチ、途中で出会ったムービーとともに一覧にします。`DOKURO_AUDIT=<スクリプト>:<エントリーポイント>` で別の場所から始められます（エンディングなど。例：`121:sure1`）。

Windows では、`Tools\Tester.bat` のメニューでこれらの環境変数を設定し、ゲーム、本編のたどり（audit）、テストを起動できます。

デバッグビルドでは、移植版はこのリポジトリの直下でもディスクイメージを探します（`*.iso` は git の対象外です）。
